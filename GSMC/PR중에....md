## 두 번째, #247

검색에서 몇 번째부터 보여줄지를 계산하다가 숫자가 너무 커지면 넘쳐서 음수가 되는 버그였다.

```kotlin
.offset((page * size).toLong())   // 전
.offset(page.toLong() * size)     // 후
```

원인은 계산 순서였다. page * size는 Int끼리 곱해서 Int로 먼저 계산되고, 이미 넘친 값을 그다음에 Long으로 바꾼 거였다. 반대로 page.toLong() * size는 한쪽을 먼저 Long으로 만드니까 계산 전체가 Long으로 된다. 타입을 언제 바꾸느냐가 결과를 바꾼다는 걸 알게 됐다. 그리고 이런 버그는 평소 값으로는 절대 안 드러나서, 아주 큰 값 같은 경계값으로 테스트해야 잡힌다는 것도 배웠다.

이 PR은 처음부터 끝까지 내가 직접 한 거라서 애정이 제일 크다. 원인 찾고, 고치고, 테스트까지 다 내 손으로 짰다.

고친 건 딱 한 줄인데 진짜 재밌었다.

머지됐을 때 기분이 제일 좋았던 PR이다.

## 세 번째, #218 · #221 디스코드 알림

이게 진짜 신기하고 재밌었다. 서버 코드는 테스트 통과로만 확인하는데, 이건 PR 올리고 조금 기다리면 디스코드에 알림이 딱 뜬다. 내가 만든 게 눈앞에서 바로 움직이니까 계속 PR 올려보고 싶을 정도였다.
