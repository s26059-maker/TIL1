## PostgreSQL이란

오픈소스 관계형 데이터베이스(RDBMS). 테이블 간 관계를 지켜주고, 데이터 넣을 때 유효성 검사도 해주고, 여러 사람이 동시에 건드려도 데이터가 안 깨지게 해줌.

## 언제 쓰면 좋은지

- 엄격한 데이터 무결성이 필요할 때 (ACID를 별도 설정 없이 기본으로 완전히 지원)
- 쿼리가 단순 조회를 넘어설 때 (윈도우 함수, 재귀 쿼리, CTE, 복잡한 조인)
- 장기적으로 유연하게 확장하고 싶을 때 (오픈소스라 벤더 종속 걱정 없음)

## 핵심 강점

- **완전 무료 오픈소스**: "커뮤니티/엔터프라이즈 에디션" 나눠서 기능 자물쇠 걸어두는 다른 DB랑 다르게, 모든 기능을 모두에게 줌
- **확장 시스템**: 코어 코드 안 건드리고 기능 추가 가능. PostGIS(지리), pgvector(AI), TimescaleDB(시계열), Citus(수평 확장) 등 수천 개 확장 존재
- **MVCC (다중 버전 동시성 제어)**: 누가 레코드 수정하면 원본을 잠그는 대신 새 버전을 만듦. 마치 구글 문서에서 여러 명이 동시에 편집해도 서로 안 막히는 것처럼, 읽는 사람과 쓰는 사람이 서로를 안 막음
- **SQL 표준 준수**: SQL:2023 핵심 기능 177개 중 170개 준수. 한 회사 마음대로 정한 방식이 아니라 표준 스펙대로 동작해서 이식성이 좋음

## MySQL이랑 뭐가 다른가

- PostgreSQL: 더 엄격한 규정 준수, 정교한 쿼리, 복잡한 데이터 타입 처리에 강함
- MySQL: 설치·학습이 더 쉽고 서드파티 앱 지원이 넓음
- 지리공간/분석 쿼리/엄격한 무결성이 필요하면 PostgreSQL, 단순 웹앱이면 MySQL도 충분

## 주요 기능

- **절차적 언어 지원**: 기본 PL/pgSQL 외에 Python, Perl, JavaScript 함수도 서버에서 바로 실행 가능. 데이터가 있는 자리에서 바로 계산해버려서, 앱 서버로 데이터를 왔다갔다 안 시켜도 됨
- **인덱스 종류별 특화**
  - B-트리: 동등/범위 검색 (제일 기본, 책 색인처럼 순서대로 찾기)
  - GIN: 전체 텍스트 검색, JSON 쿼리
  - GiST: 지리/기하학 조회
  - BRIN: 시계열처럼 순서대로 쌓이는 데이터를 저장공간 적게 쓰면서 압축 인덱싱
- **내장 전문 검색**: 별도 검색엔진(Elasticsearch 같은 거) 없이도 텍스트 토큰화, 관련성 순위, 구문 강조까지 자체 처리
- **복제**: 스트리밍 복제(전체 사본, 장애조치용) / 논리적 복제(버전 달라도 특정 테이블만 골라서 복사)
- **Materialized View**: 쿼리 결과를 미리 계산해서 저장해두는 뷰. 매번 무거운 쿼리 다시 돌리는 대신 저장된 결과를 바로 꺼내 씀. **중요한 점**: 원본 데이터가 바뀌어도 자동으로 갱신되지 않아서, `REFRESH MATERIALIZED VIEW`로 직접 새로고침해줘야 함
- **RETURNING**: INSERT/UPDATE/DELETE 하면서 그 결과값을 바로 받아올 수 있는 기능. 예를 들어 INSERT 하고 나서 생성된 id 받으려고 다시 SELECT 안 날려도 됨
- **트랜잭션 DDL**: 테이블 구조 변경(ALTER TABLE 등)도 트랜잭션 안에 넣으면 롤백 가능. 마이그레이션 중간에 문제 생겨도 되돌릴 수 있음

## Schema

DB 안에서 테이블들을 묶어놓는 폴더 같은 개념. 정리가 잘되고 권한 분리에 유리함. **중요한 점**: 스키마가 다르면 테이블 이름이 똑같아도 중복으로 쓸 수 있음 (예: `sales.users`랑 `admin.users`는 별개)

## JSONB

JSON을 텍스트가 아니라 바이너리로 변환해서 저장하는 타입. 글자 그대로 저장하는 게 아니라 아래처럼 구조화해서 저장함:

```
[헤더: 키 2개짜리 객체다]
[키 목록: name, age]              ← 키가 정렬돼서 저장됨
[값 위치: name→0번지, age→8번지]   ← 어디 있는지 주소표
[값: "정성원"] [값: 17]            ← 17은 문자 "17"이 아니라 진짜 숫자로
```

이렇게 [헤더+키목록+주소표+값] 구조로 저장해두기 때문에, 파싱 안 하고 바로 특정 키 값을 찾아갈 수 있어서 조회가 빠르고 인덱싱도 됨.

## Index

값을 정렬해서 위치와 함께 저장해두는 것. 책 뒤에 색인 페이지 붙여놓은 거랑 비슷함. **중요한 점**: 조회는 빨라지지만 쓰기(INSERT/UPDATE)는 느려지고 저장공간도 더 먹으니, 아무 컬럼에나 걸지 말고 자주 검색하는 컬럼에만 거는 게 맞음

## Explain Analyze

쿼리가 실제로 어떻게 실행되는지 보여주는 실행 계획표. 인덱스를 제대로 타는지 확인할 때 씀. **중요한 점**: EXPLAIN만 쓰면 계획만 예측해서 보여주지만, ANALYZE를 붙이면 진짜로 쿼리를 실행해버림. 그래서 UPDATE/DELETE 쿼리에 EXPLAIN ANALYZE 걸 때는 트랜잭션으로 감싸고 끝나면 꼭 롤백해야 함

## 데이터 타입

기본형(숫자, 텍스트, 날짜, 불리언 등) 외에 특이한 게 많음:

- **배열**: 한 컬럼에 여러 값 저장 — 조인 테이블 안 만들어도 되는 경우 많음
- **네트워크 주소 타입**: IP 주소를 문자열 파싱 안 하고 네이티브로 이해 (서브넷 소속 여부 바로 확인)
- **범위 타입**: 예약 기간, 버전 호환 범위, 일정 등 "구간"을 자체 타입으로 표현하고 겹침/포함 여부를 연산자로 바로 체크
- **사용자 지정 타입**: 통화 코드, SKU 형식처럼 도메인에 맞는 타입을 직접 만들어서 인덱싱·연산자까지 다 붙일 수 있음

## 클라우드/관리형 서비스

- Amazon RDS, Azure Database for PostgreSQL, Google Cloud SQL — 백업/확장/장애조치를 자동으로 처리해줘서 앱 로직에만 집중 가능
- Supabase처럼 PostgreSQL + 인증 + 실시간 구독 + 자동 API를 묶어서 주는 특화 플랫폼도 있음
- 서버리스 PostgreSQL은 안 쓸 땐 0으로 줄어들어서 비용 효율적
