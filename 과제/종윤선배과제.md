

## AOP (관점 지향 프로그래밍)
 뜻 : 공통 기능을 따로 빼서 관리하는 것

### 설명

모든 메서드마다 이런 게 들어간다고 해보자
- 로그 찍기
- 시간 측정
- 권한 체크
<pre>메서드1 → 로그
메서드2 → 로그
메서드3 → 로그
</pre>

이러면 코드가 더러움<br>
<strong>but</strong><br>
AOP를 적용하면
공통 기능을 따로 빼버림

그게 뭔 뜻이냐

### 예시)

너는 지금 햄버거 만드는 직원이라 가정했을 때<br>
햄버거를 만드는건 <strong> 핵심 기능 </strong>

그런데 

- 주문 기록 남겨라 (로그)
- 위생 체크해라 (보안)
- 시간 측정해라 (성능)

같은걸 직접 계속 해야함

거기서 AOP 방식을 쓰면<br>
<strong>너는 그냥 햄버거만 만듦</strong> 나머지는 누가 하냐?<br>
---> 자동으로 처리됨

## DB 트랜잭션

- DB가 직접 보장하는 **물리적인 작업 단위**
- `BEGIN` ~ `COMMIT/ROLLBACK` 사이의 쿼리 묶음. 이 안에서는 "전부 성공 아니면 전부 취소"가 보장됨
- 실행되는 동안 락(다른 사람이 못 건드리게 잠그는 것)과 DB 커넥션을 계속 잡고 있음 → 그래서 최대한 짧게 끝내는 게 원칙

## 애플리케이션 트랜잭션

- 비즈니스 관점에서 "하나의 작업"으로 묶이는 **논리적인 단위**
- DB 트랜잭션 여러 개에 걸쳐 있을 수 있음
- 비유: DB 트랜잭션 = 계산대에서 결제 한 번, 애플리케이션 트랜잭션 = 마트 장보기 전체 과정

## 동기

- 요청하면 **결과가 나올 때까지 기다렸다가** 다음 일을 하는 방식

```java
public static void main(String[] args) {
    String coffee = makeCoffee(); // 3초 동안 여기서 멈춤 (블로킹)
    System.out.println(coffee);
    System.out.println("다른 일 하기"); // 커피가 끝나야 실행됨
}

static String makeCoffee() {
    try { Thread.sleep(3000); } catch (InterruptedException e) {}
    return "커피 완성";
}
```

## 비동기

- 요청만 **던져놓고 바로 다음 일을 하는** 방식. 결과는 나중에 완성되면 받음

```java
public static void main(String[] args) throws Exception {
    CompletableFuture.supplyAsync(() -> makeCoffee()) // 다른 스레드한테 맡김
        .thenAccept(System.out::println); // 완성되면 이걸 실행해줘 (진동벨)

    System.out.println("다른 일 하기"); // 안 기다리고 바로 실행됨

    Thread.sleep(4000); // 메인이 먼저 종료되지 않게 잠깐 대기용
}
```

## 동기가 좋은 상황

- **결과가 지금 당장 필요할 때** (다음 로직이 그 결과에 의존)


## 비동기가 좋은 상황

- **오래 걸리는데 결과를 바로 안 써도 될 때** (사용자를 기다리게 하면 손해)
- 느린 외부 API 호출

## 격리 수준

- READ UNCOMMITTED 
    - 커밋 안 된 것도 보임 (거의 안 씀) 

- READ COMMITTED
    - 커밋된 것만 보임 

- REPEATABLE READ
    - 트랜잭션 안에선 같은 걸 읽으면 항상 같은 값 → **MySQL 기본값**

- SERIALIZABLE 
    - 완벽 격리, 대신 제일 느림
