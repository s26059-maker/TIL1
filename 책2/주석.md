# 주석

## 주석의 종류와 목적

주석은 크게 두 갈래다. **누가 읽느냐**로 나뉜다.

| 종류 | 형태 | 읽는 사람 | 목적 |
|---|---|---|---|
| 문서화 주석 | `/** ... */` (KDoc) | **사용하는 사람** | 구현을 안 열어보고도 쓸 수 있게 |
| 비형식 주석 | `// ...` | **고치는 사람** | 코드만으로는 모를 배경을 남김 |

```kotlin
/**
 * 주문 금액에 쿠폰을 적용한 최종 결제 금액을 반환한다.   ← 문서화 주석
 */
fun applyCoupon(order: Order, coupon: Coupon): Int {
    // 정산팀 요청으로 원 단위는 버림 (기획 #412)          ← 비형식 주석
    return (order.amount - coupon.discount) / 10 * 10
}
```

주석의 목적은 딱 하나로 정리된다. **코드가 스스로 말할 수 없는 것만 말하기.**

```kotlin
// 나쁨 — 코드를 그대로 한국어로 옮김
// user의 point를 3 곱한다
val bonus = user.point * 3

// 좋음 — 코드가 절대 담을 수 없는 "왜"
// 2024 가입 이벤트 정책상 3배 적립 (2024-12-31 종료 예정)
val bonus = user.point * EVENT_BONUS_RATE
```

```kotlin
// 나쁨 — 주석으로 때움
// 19세 이상이고 정지되지 않은 활성 회원인지 확인
if (u.age >= 19 && !u.banned && u.status == "A") { ... }

// 좋음 — 주석이 필요 없어짐
if (user.isActiveAdult()) { ... }
```

## 문서화 주석

**API로 노출되는 것**에 붙인다. 공개 클래스, 공개 함수, 인터페이스, 상수처럼 남이 가져다 쓰는 요소가 대상이다. Kotlin에서는 KDoc 형식(`/** */`)을 쓴다.

```kotlin
/**
 * 사용자의 주문을 생성하고 결제를 요청한다.
 *
 * 재고가 부족하거나 결제가 실패하면 주문은 생성되지 않는다.
 *
 * @param userId 주문자 ID
 * @param items 주문 상품 목록. 비어 있으면 안 된다
 * @return 생성된 주문
 * @throws OutOfStockException 재고가 부족한 경우
 * @throws PaymentFailedException 결제가 거절된 경우
 */
fun createOrder(userId: Long, items: List<OrderItem>): Order
```

문서화 주석에 꼭 들어가야 하는 것들이다.

- **요약**: 이 요소가 무엇인지 한 문장
- **상세**: 조건, 제약, 주의사항
- `@param`: 인수의 의미와 허용 범위
- `@return`: 무엇을 돌려주는지 (특히 `null` 가능성)
- `@throws`: 어떤 상황에 어떤 예외가 나는지

### 요약에서 설명하는 내용을 적는 기법

요약은 **첫 문장 하나**로 끝난다. 목록에서 이 한 줄만 보이기 때문에, 여기서 승부가 난다.

**1) 주어를 생략하고 동사로 시작한다**
"이 함수는"은 당연하니 빼고, 바로 동작부터 쓴다.

```kotlin
// 나쁨
/** 이 메서드는 사용자를 조회하는 기능을 담당하는 메서드입니다. */

// 좋음
/** ID로 사용자를 조회한다. */
```

**2) 종류에 따라 품사를 맞춘다**

```kotlin
/** 주문을 취소한다. */                       // 함수 → 동사로 끝
fun cancelOrder(id: Long)

/** 결제 수단별 결제 요청을 담당하는 클라이언트. */   // 클래스 → 명사구로 끝
interface PaymentClient

/** 재고가 부족한 경우 발생하는 예외. */            // 예외 → 명사구
class OutOfStockException : RuntimeException()

/** 한 번의 주문에 담을 수 있는 최대 상품 수. */      // 상수 → 명사구
const val MAX_ORDER_ITEM_COUNT = 20
```

**3) "어떻게"가 아니라 "무엇을"을 쓴다**
구현 방식은 바뀌지만 목적은 잘 안 바뀐다.

```kotlin
// 나쁨 — 구현을 설명. HashMap 빼면 주석이 거짓말이 됨
/** HashMap을 순회하며 캐시에서 사용자를 찾아 반환한다. */

// 좋음 — 목적만
/** ID에 해당하는 사용자를 반환한다. */
```

**4) 요약에 조건을 욱여넣지 않는다**
조건, 예외, 제약은 **아래 단락으로 내린다.**

```kotlin
// 나쁨 — 한 문장에 전부 밀어 넣음
/** 주문을 생성하는데 재고가 없으면 예외가 발생하고 결제 실패 시에도 예외가 발생하며 items가 비면 안 된다. */

// 좋음 — 요약 한 줄 + 빈 줄 + 상세
/**
 * 주문을 생성하고 결제를 요청한다.
 *
 * 재고 부족 또는 결제 실패 시 주문은 저장되지 않는다.
 */
```

**5) 이름을 그대로 늘어놓지 않는다**
이름으로 이미 아는 걸 반복하면 주석 값이 0이 된다.

```kotlin
// 나쁨 — 이름 그대로
/** 사용자를 저장한다. */
fun saveUser(user: User)

// 좋음 — 이름이 말 못 하는 걸 추가
/**
 * 사용자를 저장한다.
 *
 * 이미 같은 이메일이 존재하면 저장하지 않고 기존 사용자를 반환한다.
 */
fun saveUser(user: User): User
```

**6) `null`과 빈 값의 의미를 밝힌다**
읽는 사람이 가장 궁금해하는 지점이다.

```kotlin
/**
 * 이메일로 사용자를 조회한다.
 *
 * @return 해당 사용자. 존재하지 않으면 `null`
 */
fun findByEmail(email: String): User?

/**
 * 사용자의 주문 목록을 반환한다.
 *
 * @return 주문 목록. 주문이 없으면 빈 리스트 (`null` 아님)
 */
fun findOrders(userId: Long): List<Order>
```

### 안티 패턴

**1) 코드를 그대로 번역한 주석**

```kotlin
// 나쁨
/** count를 1 증가시킨다. */
fun increaseCount() { count++ }
```

**2) 시그니처를 그대로 옮긴 `@param`**

```kotlin
// 나쁨 — 타입만 반복
/**
 * @param userId 유저 아이디
 * @param amount 금액
 */

// 좋음 — 제약과 단위를 알려줌
/**
 * @param userId 주문자 ID. 탈퇴한 사용자면 예외 발생
 * @param amount 결제 금액(원). 0 이하일 수 없다
 */
```

**3) 유령 주석 (코드는 바뀌었는데 주석은 그대로)**

```kotlin
// 나쁨 — 최대 3회로 바뀐 지 오래
/** 최대 5회까지 재시도한다. */
fun retry(times: Int = 3)
```

**4) 틀린 주석**
없는 주석보다 **틀린 주석이 더 해롭다.** 읽는 사람은 주석을 믿고 코드를 안 읽기 때문이다.

> **중요한 점** 코드를 고칠 때 **주석도 같은 커밋에서 고친다.** 주석은 코드의 일부지 별첨 문서가 아니다.

## 비형식 주석

**구현 안에** 짧게 남기는 주석. 대상은 "이 코드를 나중에 고칠 사람"이다.

이럴 때 쓴다.

**1) 이상해 보이지만 이유가 있는 코드**

```kotlin
// 외부 API가 200과 함께 에러 body를 주는 경우가 있어 body까지 검사해야 함
if (response.isSuccessful && response.body?.errorCode == null) { ... }
```

**2) 외부 제약 / 히스토리**

```kotlin
// PG사 규격상 금액은 문자열로 보내야 함 (연동 문서 v2.3)
val body = mapOf("amount" to amount.toString())
```

**3) 성능을 위해 일부러 복잡하게 짠 곳**

```kotlin
// N+1로 응답 3초 → fetch join으로 200ms (2024-05 부하 테스트 결과)
@Query("select o from Order o join fetch o.items where o.userId = :userId")
fun findAllWithItems(userId: Long): List<Order>
```

**4) 알려진 한계와 할 일**
태그를 붙여 검색 가능하게 만든다.

```kotlin
// TODO: 쿠폰 중복 적용 정책 확정되면 분기 추가 (#312)
// FIXME: 동시 요청 시 재고가 음수가 될 수 있음
// HACK: 라이브러리 버그 우회. 3.2.0 업그레이드 시 제거 가능
```

> **중요한 점** `TODO`에는 **이슈 번호나 조건**을 같이 적는다. 근거 없는 TODO는 아무도 못 지우고 영원히 남는다.

### 안티 패턴

**1) 주석 처리된 코드**
지운다. 이력은 Git이 기억한다.

```kotlin
// 나쁨
fun createOrder(request: OrderRequest) {
    // val discount = calculateDiscount(request)
    // if (discount > 0) { ... }
    orderRepository.save(request.toOrder())
}
```

**2) 구역 나누기 주석**
주석으로 구역을 나눠야 할 만큼 길다면 **함수를 쪼개라는 신호**다.

```kotlin
// 나쁨
fun processOrder(request: OrderRequest) {
    // ===== 검증 =====
    ...
    // ===== 금액 계산 =====
    ...
    // ===== 저장 =====
    ...
}

// 좋음 — 함수 이름이 주석을 대신함
fun processOrder(request: OrderRequest) {
    validate(request)
    val total = calculateTotal(request.items)
    save(request, total)
}
```

**3) 이력 주석**

```kotlin
// 나쁨 — Git이 다 아는 정보
// 2024-03-01 홍길동 최초 작성
// 2024-04-12 김철수 할인 로직 추가
// 2024-05-03 이영희 버그 수정
class OrderService { ... }
```

**4) 감정 / 잡담 주석**

```kotlin
// 나쁨
// 이거 왜 되는지 나도 모름 ㅋㅋ
// 건드리지 마세요 제발
```

정말 이유를 모른다면 **모른다는 사실 자체를 정보로** 남긴다.

```kotlin
// 좋음
// 이 delay를 빼면 결제 콜백이 유실됨. 원인 미확인 (#508에서 조사 중)
Thread.sleep(200)
```

**5) 당연한 걸 설명하는 주석**

```kotlin
// 나쁨
val list = mutableListOf<User>()   // 유저 리스트 생성
i++                                // i를 1 증가
```
