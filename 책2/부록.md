# 부록. 예제에 쓴 코틀린 문법

## val과 var

`val`은 **다시 대입할 수 없는 것**, `var`는 **다시 대입할 수 있는 것**이다.

```kotlin
val name = "정성원"
// name = "다른이름"   ← 컴파일 에러

var count = 0
count = 1              // OK
```

주의할 게 하나 있다. **`val`은 "참조가 안 바뀐다"는 뜻이지 "내용이 안 바뀐다"는 뜻이 아니다.**

```kotlin
val items = mutableListOf(1, 2, 3)
items.add(4)          // OK — 리스트 내용은 바뀜
// items = mutableListOf()  ← 이건 에러
```

## 클래스와 주 생성자

Kotlin은 클래스 선언과 동시에 생성자와 필드를 만든다.

```kotlin
// 생성자 인수에 val을 붙이면 그대로 프로퍼티가 됨
class User(val name: String, val age: Int)

val user = User("정성원", 18)
println(user.name)     // 접근 가능
```

```kotlin
// val을 안 붙이면 생성자 인수로만 쓰이고 프로퍼티는 안 생김
class User(name: String) {
    val upperName = name.uppercase()
    // println(name)  ← 함수 안에서는 못 씀
}
```

```kotlin
// private val — 밖에서 접근 불가
class OrderService(private val paymentClient: PaymentClient)
```

## data class

**값을 담는 용도**의 클래스. `equals`, `hashCode`, `toString`, `copy`를 자동으로 만들어 준다.

```kotlin
data class Money(val amount: Int)

val a = Money(1000)
val b = Money(1000)
println(a == b)        // true — 값이 같으면 같다고 판단
println(a)             // Money(amount=1000)

val c = a.copy(amount = 2000)   // 일부만 바꾼 새 객체
```

일반 클래스는 이렇게 안 된다.

```kotlin
class Money(val amount: Int)
println(Money(1000) == Money(1000))   // false — 주소를 비교함
```

## 프로퍼티와 커스텀 getter

`get()`을 직접 정의하면 **값을 저장하지 않고 매번 계산**한다.

```kotlin
class Cart {
    private val _items = mutableListOf<Item>()

    // 매번 계산 — 저장 공간을 쓰지 않음
    val count: Int get() = _items.size
    val totalPrice: Int get() = _items.sumOf { it.price }
}
```

`get()` 없이 쓰면 값이 **한 번만 계산되고 고정**된다.

```kotlin
val count: Int = _items.size    // 객체 만들 때의 값으로 굳어짐
```

### private set

**읽기는 밖에서, 쓰기는 안에서만** 되게 만든다.

```kotlin
class GameCharacter {
    var hp: Int = 100
        private set          // 밖에서 character.hp = 0 불가

    fun takeDamage(damage: Int) {
        hp -= damage         // 안에서는 가능
    }
}
```

### field

setter를 직접 쓸 때, **자기 자신을 가리키는 예약어**다. `field` 대신 프로퍼티 이름을 쓰면 setter가 자기를 다시 부르며 무한 반복된다.

```kotlin
class Invoice {
    var amount: Int = 0
        set(value) {
            check(!isConfirmed) { "확정된 청구서는 수정 불가" }
            field = value    // 실제 저장소에 대입
        }
}
```

## 식 본문 (=)

함수 몸통이 **값 하나로 끝나면** 중괄호와 `return` 없이 `=`로 쓸 수 있다.

```kotlin
// 블록 본문
fun isAdult(user: User): Boolean {
    return user.age >= 19
}

// 식 본문 — 같은 뜻
fun isAdult(user: User): Boolean = user.age >= 19
```

## if와 when이 값이 되는 것

Kotlin에서 `if`, `when`, `try`는 **문(statement)이 아니라 식(expression)** 이다. 즉 **값을 돌려준다.**

```kotlin
// Java식 — 변수 만들고 나중에 채움
var grade: String
if (score >= 90) grade = "A" else grade = "B"

// Kotlin식 — if 자체가 값
val grade = if (score >= 90) "A" else "B"
```

### when

`switch`의 강화판이다. 조건식으로도, 값 비교로도 쓴다.

```kotlin
// 값 비교
val label = when (status) {
    OrderStatus.PENDING -> "결제 대기"
    OrderStatus.PAID    -> "결제 완료"
    else                -> "기타"
}

// 조건식 — 괄호 없이
val grade = when {
    score >= 90 -> "A"
    score >= 80 -> "B"
    else        -> "C"
}
```

> **중요한 점** `when`을 **값으로 쓰면** 모든 경우를 다 처리해야 컴파일된다. enum이나 sealed에 케이스가 추가되면 컴파일 에러로 알려주므로, 빠뜨릴 수가 없다.

## enum class

**정해진 몇 가지 값만** 가질 수 있는 타입이다.

```kotlin
enum class OrderStatus { PENDING, PAID, SHIPPED, DELIVERED, CANCELED }
```

enum 안에 함수도 넣을 수 있다. 세미콜론(`;`)으로 값 목록의 끝을 표시한다.

```kotlin
enum class OrderStatus {
    PENDING, PAID, SHIPPED, DELIVERED, CANCELED;   // ← 세미콜론 필수

    fun canMoveTo(next: OrderStatus): Boolean = when (this) {
        PENDING   -> next in setOf(PAID, CANCELED)
        PAID      -> next in setOf(SHIPPED, CANCELED)
        SHIPPED   -> next == DELIVERED
        DELIVERED -> false
        CANCELED  -> false
    }
}
```

## sealed interface / sealed class

**"이 타입이 될 수 있는 건 여기 적힌 것뿐"** 이라고 못 박는 문법이다. enum과 다른 점은 **각 경우가 서로 다른 데이터를 가질 수 있다는 것**이다.

```kotlin
sealed interface LoadResult {
    data object Loading : LoadResult                     // 데이터 없음
    data class Success(val data: List<User>) : LoadResult  // 데이터 있음
    data class Failure(val message: String) : LoadResult   // 메시지 있음
}
```

```kotlin
when (result) {
    is LoadResult.Loading -> showSpinner()
    is LoadResult.Success -> render(result.data)      // 여기선 data 접근 가능
    is LoadResult.Failure -> showError(result.message)
}
// else 없이도 컴파일됨 — 가능한 경우를 컴파일러가 다 알기 때문
```

`data object`는 **인스턴스가 하나뿐인 경우**(담을 데이터가 없을 때) 쓴다.

## object와 companion object

```kotlin
// object — 인스턴스가 하나뿐인 싱글턴
object ShippingPolicy {
    const val FREE_SHIPPING_THRESHOLD = 50_000
    fun isFree(amount: Int): Boolean = amount >= FREE_SHIPPING_THRESHOLD
}

ShippingPolicy.isFree(60_000)   // 생성 없이 바로 사용
```

```kotlin
// companion object — 클래스에 딸린 정적 영역 (Java의 static 자리)
data class UserResponse(val name: String) {
    companion object {
        fun from(user: User) = UserResponse(user.name)
    }
}

UserResponse.from(user)   // 클래스 이름으로 호출
```

## const val

**컴파일 시점에 값이 정해지는 상수.** 숫자, 문자열 같은 기본 타입에만 붙일 수 있다.

```kotlin
const val MAX_RETRY_COUNT = 3
const val FREE_SHIPPING_THRESHOLD = 50_000    // 언더스코어로 자릿수 구분 가능
```

## null 안전

Kotlin은 **null이 될 수 있는 타입과 없는 타입을 구분**한다. 타입 뒤에 `?`가 붙으면 null이 가능하다는 뜻이다.

```kotlin
val a: String = "hi"     // null 불가
val b: String? = null    // null 가능
```

### ?. (안전 호출)

앞이 null이면 **호출을 건너뛰고 null을 돌려준다.**

```kotlin
val length = user?.name?.length   // user나 name이 null이면 결과도 null
```

### ?: (엘비스 연산자)

**앞이 null이면 뒤 값을 쓴다.** 기호가 엘비스 프레슬리 머리 모양을 닮아서 붙은 이름이다.

```kotlin
val name = user?.name ?: "이름 없음"

// 뒤에 return이나 throw도 올 수 있음 — 조기 반환에 자주 씀
val user = repository.find(id) ?: return
val user = repository.find(id) ?: throw UserNotFoundException()
```

### !! (강제)

**null이 아니라고 우기는 것.** null이면 그 자리에서 예외가 난다. 되도록 쓰지 않는다.

```kotlin
val name = user!!.name   // user가 null이면 NullPointerException
```

### ?.let

**null이 아닐 때만 블록을 실행**한다.

```kotlin
user?.let {
    mailSender.send(it.email)   // user가 null이면 아예 실행 안 됨
}

// 값을 돌려받는 형태로도 씀
repository.findByKey(key)?.let { return it }
```

## 스마트 캐스트

**타입을 확인하면 그 뒤부터는 자동으로 그 타입으로 취급**된다. 따로 형변환을 안 해도 된다.

```kotlin
fun describe(value: Any?): String {
    if (value !is String) return "문자열 아님"
    return value.uppercase()      // 여기선 이미 String으로 확정
}
```

```kotlin
when (result) {
    is LoadResult.Success -> render(result.data)   // 자동으로 Success 타입
}
```

## require / check

**조건을 검사하고 아니면 예외를 던지는** 함수다. 조기 반환처럼 위에서 조건을 걷어낼 때 쓴다.

```kotlin
fun withdraw(amount: Int) {
    require(amount > 0) { "출금액은 0보다 커야 합니다" }   // 인수 검증 → IllegalArgumentException
    check(!isLocked) { "잠긴 계좌입니다" }                 // 상태 검증 → IllegalStateException
    balance -= amount
}
```

중괄호 안의 메시지는 **조건이 깨졌을 때만 만들어진다.** 그래서 문자열 조립 비용이 평소엔 안 든다.


## 확장 함수

**남의 클래스에 함수를 덧붙이는 문법.** 원본 코드를 안 고치고도 메서드처럼 쓸 수 있다.

```kotlin
private fun String.normalized(): String = trim().lowercase()

"  Hello  ".normalized()   // "hello"
```

```kotlin
// 내 클래스에도 자주 씀 — 조건에 이름 붙이기
private fun User.isActiveAdult(): Boolean =
    age >= 19 && status == "A" && !banned

users.filter { it.isActiveAdult() }
```

함수 안에서 `this`는 생략할 수 있어서, `trim()`은 사실 `this.trim()`이다.

## 람다와 it

중괄호로 쓰는 **이름 없는 함수**다. 인수가 하나면 이름을 생략하고 `it`으로 쓸 수 있다.

```kotlin
users.filter { user -> user.isActive }   // 이름 붙인 형태
users.filter { it.isActive }             // it으로 생략
```

함수의 **마지막 인수가 람다면 괄호 밖으로 뺄 수 있다.**

```kotlin
users.filter({ it.isActive })   // 원래 형태
users.filter { it.isActive }    // 괄호 밖으로
```

## 컬렉션 함수

반복문 대신 **"결과가 무엇인지"를 정의**하는 데 쓴다.

```kotlin
val users: List<User> = ...

users.filter { it.isActive }              // 조건에 맞는 것만 남김
users.map { it.name }                     // 각 원소를 변환
users.sumOf { it.price }                  // 전부 더함
users.sortedByDescending { it.price }     // 정렬 (내림차순)
users.take(3)                             // 앞에서 3개
users.groupBy { it.type }                 // Map<Type, List<User>> 로 묶음
users.any { it.isBanned }                 // 하나라도 있으면 true
users.isEmpty() / users.isNotEmpty()
```

```kotlin
// 이어 붙여 쓰기
val topNames = users
    .filter { it.isActive }
    .sortedByDescending { it.point }
    .take(3)
    .map { it.name }
```

```kotlin
// Map 다루기
salesByType.mapValues { (_, orders) -> orders.sumOf { it.price } }
entries.associate { it.key to it.value }    // Map으로 되돌림
```

`_`는 **안 쓰는 값**을 표시하는 자리다.

## List와 MutableList

```kotlin
val fixed: List<Item> = listOf(a, b)              // 읽기 전용
val mutable: MutableList<Item> = mutableListOf()  // 추가/삭제 가능

mutable += item        // add와 같음
mutable -= item        // remove와 같음
mutable.toList()       // 읽기 전용 복사본
```

밖으로 내보낼 땐 `List`로, 안에서만 `MutableList`로 쓰는 게 기본 패턴이다.

```kotlin
class Cart {
    private val _items = mutableListOf<Item>()
    val items: List<Item> get() = _items.toList()
}
```

## 인터페이스와 override

```kotlin
interface PaymentClient {
    fun pay(amount: Int): PaymentResult
}

class TossPaymentClient : PaymentClient {

```

Kotlin은 **클래스와 메서드가 기본적으로 상속 불가**다. 상속을 허용하려면 `open`을 붙여야 한다.

```kotlin
class AdminUser : User()
```

## coerceAtLeast / coerceIn

**값을 범위 안으로 가두는** 함수다. `if`로 쓰던 걸 짧게 만든다.

```kotlin
// if 버전
if (total < 0) total = 0

// coerce 버전
val total = discounted.coerceAtLeast(0)     // 최소 0
val hp = (hp - damage).coerceAtLeast(0)
val rate = value.coerceIn(0, 100)           // 0~100 사이로
```

## in과 setOf

`in`은 **포함 여부**를 확인한다.

```kotlin
next in setOf(PAID, CANCELED)     // next가 둘 중 하나인가
score in 80..89                   // 범위 안에 있는가
```

## lateinit

**나중에 값을 넣겠다고 미루는** 선언이다. 값을 넣기 전에 쓰면 예외가 난다.

```kotlin
class OrderService {
    @Autowired lateinit var paymentClient: PaymentClient
}
```

> **중요한 점** `lateinit`은 **의존이 생성자에 안 보이게** 만들기 때문에 되도록 피하고, 생성자 주입을 쓴다.

```kotlin
// 이 형태가 기본
class OrderService(private val paymentClient: PaymentClient)
```
